**13. 修复：工具并行卡死（执行中一直闪）**
- 现象：多工具并行时卡片停在"执行中"（tool_start 有、tool_end 无），无任何输出
- 根因：`get_group_stats` 的 `storageBytes` 是 PG 的 `Decimal`，`json.dumps` 抛 `TypeError` → 工具异常 → LangGraph 只发 `on_tool_error` 不发 `on_tool_end` → 前端卡片永不更新
- 修复：a) `storageBytes` 转 `int`；`_ok` 加 `default=str` 防御  b) facade 捕获 `on_tool_error` → 补发 `tool_end(status=failed)`，卡片能正确结束
- 验证：用户同款问题"查看群组「知识库」的统计信息和成员列表"3 工具并行全部 start/end 配对，落库 USER→3×TOOL→ASSISTANT

**14. 修复：消息徽标错误显示 kb_search**
- `AssistantMessage.vue` 的 mode tag 只有 CHAT/KB_SEARCH 两分支，ADMIN 落入 kb_search
- 改为三态（admin 徽标琥珀色），新增 `--admin` 样式

**15. 修复：流式回答不显示 + 工具卡片不更新（刷新后才显示）**
- 现象：流式期间回答不渲染、工具卡片停在"执行中"，刷新后从 DB 加载才正常
- 根因 1：router 把 delta 事件的 data 直接序列化为字符串（`"文本"`），前端解析约定 `{"delta":"文本"}` → `ev.delta` 取不到 → 回答不流式显示
- 根因 2：后端 tool 事件 data 是顶层字段 `{id,name,args,result,status}`，前端却读 `ev.toolCall`（undefined）→ tool_end 被忽略 → 卡片永远"执行中"
- 修复：router delta 包成 `{"delta": ...}`；前端 onStreamEvent 改读顶层字段（toolId/toolName/toolArgs/toolResult/toolStatus），types 同步扩展

**17. 写操作升级为 interrupt 硬确认（human-in-the-loop）**
- 背景：对话确认（Agent 文字询问"请确认？"）用户不满意，期望界面确认按钮
- 机制：写工具（ban_group/unban_group/delete_document）内部 `interrupt({type/action/target/impact})` 暂停图执行 → SSE 发 `confirmation` 事件 → 前端确认卡片（确认执行/取消按钮）→ 用户点击后再次请求 stream 带 `resume: "confirm"/"cancel"` → LangGraph `Command(resume=...)` 恢复 → 工具继续执行
- 改动：
  - `tools.py`：3 个写工具 + `_confirm_interrupt` 辅助（interrupt 返回确认信息）
  - `facade.py`：中断检测改读 `state.tasks[].interrupts`（langgraph 1.2 API，非 state.values）；`chat_stream` 支持 resume 参数（`Command(resume=...)` 恢复）
  - `service.py`：resume 分支跳过 USER 消息保存/记忆维护；被中断的首次流不落空 ASSISTANT 消息；ADMIN 指令改为"写操作直接调用工具，不要文字确认"
  - `schemas.py` / `router.py`：ChatRequest 加 resume 字段并透传
  - 前端：`confirmation` 事件 → 确认卡片（琥珀色警告 + 确认/取消按钮）；`resumeInterrupted()` 再次 stream 绑定同一消息；types 加 `AssistantConfirmation`
- 排查过程：interrupt 触发但图未暂停的假象——实际图暂停正常（`state.next=('tools',)`），是中断信息读取 API 用错（langgraph 1.2 在 `state.tasks[].interrupts`）
- 验证（_test_confirm.py）：① 暂停生效（confirmation 事件 + 群组保持 ACTIVE）② resume confirm 执行（DISABLED）③ resume cancel 不执行（保持 DISABLED）④ 环境还原；全部通过

**18. 修复：确认卡片不显示 + 多中断合并**
- 现象：写工具卡片显示"失败"（Interrupt 值被当错误）、无确认卡片
- 根因 1：on_tool_error 分支把 GraphInterrupt 当普通错误发了 tool_end(failed)——改为 isinstance 检查跳过（interrupt 是正常暂停）
- 根因 2：前端读 `ev.confirmation`，后端发扁平字段——改为从顶层字段构造 AssistantConfirmation
- 根因 3（多中断）：「把所有群组都停用了」触发 2 个并发 interrupt，resume 报 "must specify the interrupt id"——langgraph 要求 resume 值格式为 `{interrupt_id: value}`（xxh3_128 hex digest），且 confirmation 需合并展示
- 修复：confirmation 检测收集全部 interrupts 合并为一张确认卡片（target 拼接 + count）；resume 前 aget_state 读全部 interrupt id 构造 map
- 验证：单中断（确认执行/取消）与多中断（2 个群组合并确认 → 一次确认全部执行）均通过，环境还原

**19. 修复：QA stream-ask 群组停用时 500（response already started）**
- 现象：群组被停用后，用户在该群组提问 QA → `POST /api/qa/stream-ask` 报 `RuntimeError: Caught handled exception, but response already started`（500）
- 根因：`require_group_access` 在 SSE event_generator **内部**执行——响应 headers 已发出后抛 ForbiddenException，Starlette 无法返回 403 → 500
- 修复：权限检查移到 handler 函数体（构造 StreamingResponse 之前），拒绝时正常返回 403
- 检查了其他 SSE 端点（assistant chat_stream 等在函数体检查），无同类问题
