## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                       前端（Vue 3 + Element Plus）             │
│  Home / 登录 │ 文档管理 │ QA（云端历史/续聊）│ AI 助手 │ 群组 │ 管理控制台 │
│  （Axios + snake→camel 拦截器；SSE 流式用 fetch 手动解析）     │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP /api（Vite 代理 :10001）
┌──────────────────────────┴──────────────────────────────────┐
│                    FastAPI 后端（应用层）                      │
│  ┌─────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌──────────┐  │
│  │ auth    │ │ user   │ │ group  │ │ document│ │ qa       │  │
│  │ JWT认证 │ │ 用户管理│ │ 群组协作│ │ 上传/删 │ │ 规划/检索 │  │
│  └─────────┘ └────────┘ └────────┘ └────────┘ └───┬──────┘  │
│  ┌─────────┐ ┌────────┐ ┌────────┐ ┌────────┐    │         │
│  │ assistant│ │ metrics│ │ audit  │ │ system │ ┌─┴──────┐  │
│  │ Agent+记忆│ │ 统计/洞察│ │ 审计留痕│ │ 健康检查│ │ ingestion│ │
│  └─────────┘ └────────┘ └────────┘ └────────┘ │ ETL worker │
│  ┌────────────────────────────────────────────┴──────────┐  │
│  │                    engine（基础设施适配层）               │  │
│  │  vector_store（PGvector 原生 SQL）│ es_service │ storage │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────┬──────────────────┬──────────────────┬─────────────┘
           │                  │                  │
     PostgreSQL 16      Elasticsearch 8     MinIO（对象存储）
     + pgvector         （IK 分词）          （文档/分片）
```

**分层原则**：
- **Router（薄）**：参数校验、鉴权依赖、审计埋点，不写业务逻辑
- **Service（业务）**：数据库操作、编排；接受显式传参（user_id/session）
- **Engine（适配层）**：基础设施访问，自研 SQL，不依赖 LangChain 向量存储
- **后台任务**：ingestion worker（2s 轮询）+ 上传清理（1h 周期）

## 2. 数据模型

### 2.1 核心表

| 表 | 用途 | 关键字段 |
|---|---|---|
| `users` | 用户 | username/email 唯一、password_hash(bcrypt)、system_role、status、must_change_password |
| `user_refresh_tokens` | Refresh 令牌 | token_id、token_hash、expires_at、revoked_at（旋转/重放检测） |
| `groups` | 群组 | group_code 唯一、owner_user_id、status(ACTIVE/DISABLED/DELETED) |
| `group_memberships` | 成员 | group_id+user_id 唯一、role(OWNER/MEMBER) |
| `group_invitations` / `group_join_requests` | 邀请/申请 | status(PENDING/ACCEPTED/…) |
| `documents` | 文档元数据 | group_id、file_hash、storage 路径、status(UPLOADED/PROCESSING/READY/FAILED)、failure_reason、软删 deleted |
| `document_upload_sessions` / `_chunks` | 分片上传 | upload_id、chunk_index、expires_at（24h） |
| `document_chunks` | 文档切片 | document_id、group_id、chunk_index、chunk_text、char 区间 |
| `ingestion_jobs` | 处理任务 | status(PENDING/RUNNING/SUCCEEDED/FAILED)、retry_count、next_retry_at |
| `qa_sessions` | 问答会话（一问一答或续聊聚合） | user_id、group_id、title |
| `qa_messages` | 问答消息 | role、content、thinking、citations(JSON)、reason_code、**evidence_level** |
| `assistant_sessions` | 助手会话 | user_id、status(ACTIVE/ARCHIVED/DELETED)、last_message_at |
| `assistant_messages` | 助手消息 | session_id、role(USER/ASSISTANT/TOOL)、tool_mode、structured_payload(JSON) |
| `assistant_session_contexts` | 会话记忆 | summary_text（LLM 语义摘要）、compact_summary（回退拼接）、context_version |
| `llm_usage_records` | LLM 用量 | user_id、module(qa/assistant)、endpoint、token 估算、cost_amount(CNY)、model_name、is_estimated |
| `model_configs` | 模型配置 | user_id、model_type(chat/embedding)、is_active（同类型唯一激活） |
| `audit_logs` | 审计 | user_id、username、action、target_type/id、detail(JSON) |

**向量存储**：`langchain_pg_embedding` 表（`cmetadata` JSONB 存 document_id/group_id/chunk_id/chunk_index，检索按 group_id 过滤）。

### 2.2 关键索引

- 文档：`(group_id, deleted)`、`(group_id, file_hash)`、`(status, deleted)`
- 任务：`(status, next_retry_at, created_at)` + `FOR UPDATE SKIP LOCKED` 并发领取
- 会话：`(user_id, status)`；消息：`(session_id, created_at)`
- 用量：`(user_id, created_at)`、`(group_id, created_at)`、`(module, created_at)`

## 3. 核心流程

### 3.1 文档入库（ETL）

```
上传（直传/分片+MinIO compose）
  → 创建 Document(status=UPLOADED) + IngestionJob(PENDING)
  → worker 轮询领取（SKIP LOCKED，2s）
  → PROCESSING
  → 解析（Docling PDF / python-docx / 文本）
  → 清洗（去控制字符、保代码块）
  → 结构化切块（标题分段 → 段落 → 句切；目标 240 / 最大 320 / 重叠 32 token）
  → 保存 document_chunks + preview_text
  → 向量化（batch 10）写入 pgvector（cmetadata）
  → ES 索引（IK 分词，_doc id = chunk id）
  → READY（清空 failure_reason）
失败 → FAILED + failure_reason；重试指数退避 30s·2^n，最多 3 次
删除 → 软删 + 清 chunk + 清向量 + 清 ES + 清 MinIO（逐项独立，失败 error 日志 + 接口提示）
```

### 3.2 知识库问答（QA）

```
POST /api/qa/stream-ask {groupId, question, sessionId?}
  1. 权限：require_group_access（成员 + 群组 ACTIVE）
  2. 查询规划：LLM 判定 DIRECT/REWRITE/DECOMPOSE（≤3 问句；DECOMPOSE 不含原文）
  3. 并行混合检索：对每个问句并发跑 向量(top50) + ES(top50)
  4. RRF 融合（K=60）→ top8 → 同文档相邻块聚类（±1 邻居扩展补上下文）
  5. 证据评估：raw_sim<0.65 且无双通道命中 → NONE（直接拒答，跳过 LLM）
  6. 流式生成：ChatOpenAI.astream → StreamingAnswerParser 提取 ANSWER 段 → SSE token 事件
  7. 收尾：answer / citations（含 reasonCode）/ done
  8. 落库：qa_sessions + qa_messages（evidence_level），sessionId 存在则追加
  9. 用量记录（估算 token + 实际模型单价）
```

**流式解析器**（`StreamingAnswerParser`）：按 `<<<ANSWER>>>` 进入、`<<<END>>>` 退出；保留 9 字符尾部探测结束标签，避免标签泄漏进正文；flush 尾部以 token 事件补发。

### 3.3 AI 助手（Agent）

```
POST /api/assistant/chat/stream {sessionId, message, toolMode, groupId}
  1. 权限：groupId 存在则成员校验
  2. 记忆维护：>20 条或 >8000 字符 → LLM 语义摘要（get_chat_config 取当前用户模型）
  3. 构建指令（含摘要 + 最近 10 条消息）
  4. LangGraph create_react_agent（KB_SEARCH 挂 knowledge_base_search 工具，recursion_limit=10）
  5. astream_events 捕获 on_chat_model_stream（去重前缀）→ SSE delta
  6. 落库 USER/ASSISTANT 消息 + 用量记录 + 自动标题（fire-and-forget）
```

**会话归档**：status 三态；`list_sessions` 时惰性把 >30 天未活跃的 ACTIVE 转 ARCHIVED（无后台任务）。

### 3.4 后台任务

| 任务 | 周期 | 逻辑 |
|---|---|---|
| Ingestion worker | 2s | 领取 PENDING job → 执行 → 成功/失败（退避重试） |
| 上传会话清理 | 1h | 删除过期未完成上传会话 + MinIO 分片（幂等、失败吞并） |

## 4. 接口设计

### 4.1 约定

- 前缀：`/api`；管理接口：`/api/admin/*`（`require_admin`）
- 响应：`ApiResponse{success, data, message}`；**例外**：`qa/ask`、`qa/stream-ask`、`assistant/sessions` 系列直接返回数据
- 分页：`{items, total, page, limit}`；查询参数 `page`/`limit`（≤100）
- 时间：UTC naive + `Z` 后缀
- SSE：`event: <type>\ndata: <json>\n\n`；前端 fetch + 手动 `\n\n` 解析

### 4.2 主要端点

| 模块 | 端点 |
|---|---|
| 认证 | `POST /api/auth/login/register/refresh/logout`、`GET /api/auth/me` |
| 用户 | `POST /api/account/change-password`；`/api/admin/users` CRUD + status + reset-password + create |
| 群组 | `/api/groups/*`（my/CRUD/members/leave/invitations/join-requests）；`/api/admin/groups/*`（list/detail/ban/unban/member-remove/dissolve） |
| 文档 | `/api/documents` CRUD + upload（直传/分片 init/chunk/complete）+ preview/download/chunks/retry；`/api/admin/documents`（分页/stats/retry/delete） |
| QA | `POST /api/qa/ask`、`POST /api/qa/stream-ask`；`/api/qa/sessions`（我的历史）；`/api/admin/qa/sessions`（审计） |
| 助手 | `/api/assistant/sessions`（含 archive/restore/summarize）、`messages?beforeId=`、`POST /api/assistant/chat`、`chat/stream` |
| 统计 | `/api/admin/metrics/overview|trend|rankings/*|insights` |
| 系统 | `/api/admin/health`、`/api/admin/audit-logs` |

## 5. 安全设计

| 层 | 措施 |
|---|---|
| 传输 | 无 TLS（内网部署）；Cookie SameSite=Lax、path=/api |
| 认证 | bcrypt 哈希；JWT 30min + Refresh 旋转（一次性、重放检测吊销全部） |
| 授权 | `require_group_access`（成员 + 群组状态）；**文档归属校验从 DB 解析，不信任客户端 groupId**；上传会话归属校验；管理员旁路 |
| 输入 | Pydantic 校验（长度/格式）；文件名搜索参数化 ilike |
| 输出 | DOMPurify 白名单消毒（KaTeX 输出仅 HTML span） |
| 审计 | 11 类敏感操作留痕 |
| 失败隔离 | 落库/审计/用量/清理全部 try/except 吞并，不阻断主流程 |

## 6. 关键技术决策

| 决策 | 方案 | 理由 |
|---|---|---|
| 混合检索融合 | RRF（K=60）融合向量 + ES，融合后 top 8 聚类 | 平滑排名差异；聚类 + 邻居扩展补上下文，证据完整 |
| 证据评估 | 余弦相似度 0.65 阈值 + 双通道命中判定，四级分级 | 语义无关（字面命中）直接拒答；阈值边界抖动已通过"双通道任一强命中不判 NONE"缓解（待落地） |
| 拒答短路 | NONE 不调 LLM | 省成本（实测单次省 7.4s） |
| 流式协议 | 分隔符格式 + 流式解析器 + SSE token 事件 | 兼容模型输出的结构化标签，同时实现真流式 |
| 问答落库 | 独立 qa_sessions/qa_messages（一问一答 + 续聊追加） | 管理审计 + 用户云端历史双受益 |
| 记忆压缩 | LLM 语义摘要（触发时生成）+ 拼接回退 | 可视化"AI 记住了什么"；成本可控（每压缩 1 次调用） |
| 消息分页 | 游标（before_id）而非 offset | 新消息插入不导致分页错位 |
| 归档 | 状态机 + 惰性自动归档 | 无后台任务，简单可靠 |
| 清理任务 | lifespan 周期 task | 独立、可取消、失败不影响启动 |
| 建表 | create_all + `ADD COLUMN IF NOT EXISTS` | 无迁移工具下的幂等演进 |
| 前端渲染 | marked + KaTeX 扩展 + DOMPurify 统一管线 | 三处渲染点（QA/助手/预览）行为一致，公式可渲染 |
| 趋势图 | SVG 手绘、双 Y 轴、30 天补零 | 无图表库依赖；双轴避免量级压扁 |
| 用量统计 | 估算 token（字符数/1.5）+ 模型单价表 | 无真实 token 计数的近似方案，标记 is_estimated |

## 7. 可观测性

- **访问日志**：`method path -> status (ms) userId=`（LoggingMiddleware 读 UserContext）
- **业务日志**：检索计划、证据级别、流式解析结果、任务重试、清理结果
- **审计**：敏感操作结构化留痕，管理页可查
- **健康检查**：`/api/admin/health` 聚合基础设施与队列状态
- **数据洞察**：证据质量分布（SUFFICIENT/PARTIAL/WEAK/NONE）反映 RAG 效果
